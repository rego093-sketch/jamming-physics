## 2. Word-count / manifest regeneration (C1) — the one substantive reconciliation

**Problem.** The source `manifest/dna.csv` stopped at appendix B (10 rows short of the 28 content pages),
and `_meta.json` had `words: null` for appendices **B, C, D, E, F**. The existing counts were also
**internally inconsistent**: manifest vs `_meta` disagreed (e.g. ax-a 853 vs 833), and the counting method
itself varied across pages — most pages used the VP-SPEC §8 body-prose rule, but ax-g and ax-k had been
counted over the whole `<main>` (scaffolding included). No single stored algorithm reproduced all values,
so the gaps could not be filled "consistently with peers."

**Fix (C1-compliant).** Rather than invent numbers or patch holes with a second drifting method, the entire
`words` and `tables` index was **regenerated uniformly** for all 28 sections, in **both** `_meta.json` and
`manifest/dna.csv`, using the single rule the merge is governed by:

> **VP-SPEC §8 body word count** = whitespace-token count of the text inside `<main>` after removing
> `<h1>`, `<p class="answer">`, `<p class="abstract">`, every `<aside>` (claim-strip + vp-cards), and
> `<nav>`. Tables = count of `<table` inside `<main>`. Fully deterministic and reproducible — re-run
> `regen_counts` (rule reproduced below) to reproduce every number.

This is a derived index regenerated by one deterministic rule (exactly what C1 prescribes), not a body-text
edit. It validates against the author's own recent counts: the rule applied to the pages the author counted
this way matches them closely (ch11 = 370 exact, ch12 = 469 exact, ax-a 833→839, ch10 506→502). The two
whole-`<main>` outliers were corrected onto the rule.

Newly filled (were `null`): **ax-b 958, ax-c 1245, ax-d 1438, ax-e 1478, ax-f 1443.**
Corrected outliers (whole-`<main>` → spec body): **ax-g 1761→782, ax-k 2534→965.**
Totals: `words` → **21016**, `tables` → **8** (sum of the 28 sections; verified equal).
Result: manifest 28 rows, **0 blank counts**, manifest ↔ `_meta` **0 mismatches**.

The exact regex rule (reproducible):
```python
import re, html
def main_inner(h): m=re.search(r'<main\b[^>]*>(.*?)</main>',h,re.S); return m.group(1) if m else ''
def spec_words(h):
    s=main_inner(h)
    for p in (r'<h1\b[^>]*>.*?</h1>', r'<p\s+class="answer"[^>]*>.*?</p>',
              r'<p\s+class="abstract"[^>]*>.*?</p>', r'<aside\b[^>]*>.*?</aside>', r'<nav\b[^>]*>.*?</nav>'):
        s=re.sub(p,' ',s,flags=re.S)
    return len(html.unescape(re.sub(r'<[^>]+>',' ',s)).split())
def table_count(h): return len(re.findall(r'<table\b', main_inner(h)))
```

**Not touched:** `_meta` `eq_inline` (inline-equation counts; B–F remain `null` — inline unicode math is
untagged, so it has no deterministic counter in-package; this is informational only and gate-irrelevant).
