Module 49 — SH-26 cross-system ratio: protocol harness + population template

In plain terms. Module 46 ran the "fixed-recipe" test inside one rift system and got an in-between answer, then said the real version needs the same recipe checked across different, unrelated salt basins — and that making up those numbers would break the rules, so it left the test unbuilt. This module builds the test machine and fixes the full list of basins to check (so nothing can be cherry-picked), then runs it on the one thing we can honestly fill in now: how much salt each basin holds. That alone varies by about ten-fold from basin to basin — exactly why it can't decide anything on its own. The numbers the test actually needs — the matched size of each source rock and how much each basin stretched — aren't available at trustworthy quality, so the deciding answer stays open. The honest gain: the test is now built and waiting on verified data, instead of just named.

1. Why this module exists

Module 46 built the within-system ratio test on the South Atlantic and found it inconclusive, then specified the only decisive version — the same cross-control ratio across independent salt-giant systems — and stated plainly that fabricating those numbers would violate the framework, so it is left [O]/unbuilt rather than guessed. Leaving a named test entirely unbuilt is a finalization gap; fabricating its inputs is forbidden. This module takes the honest middle path: build the machine, fix the population, run on what is verifiable, and pin exactly what is missing.

2. The protocol (what would decide SH-26)

One conserved relaxation (one parameter) makes the cross-control ratio source_volume / extension (and salt / source) a universal constant across independent systems ⇒ low CV. The independent-magnitude mainstream makes those ratios scatter ⇒ high CV. Pre-registered rule (declared before the data is read): CV < 0.15 tight (one-parameter); CV > 0.35 scattered (mainstream); between = inconclusive.

3. The canonical population (no cherry-picking)

The population is fixed in advance to the canonical salt giants — Messinian, Louann, Zechstein, South Atlantic Aptian, Red Sea, Pricaspian — each row carrying explicit quality flags: LIT_OOM (literature order-of-magnitude, citable, not verified primary) and TBV (to-be-verified, left blank, skipped by the harness). Salt volume is the only column responsibly fillable now; matched source volume and extension are TBV by design.

4. What the run shows now

Across the six systems, present-tense salt volume scatters ~10× (CV = 0.58). This is expected and is not the discriminator: salt volume tracks basin size and accommodation in both frameworks. The discriminating cross-control ratio cannot be computed because every system still needs verified source_volume_km3 and extension_strain; the harness prints exactly which fields each system needs and runs no fabricated values.

5. Grade and what it means for the cascade

The cross-system SH-26 protocol is now built and pre-registered ([L]), the population is fixed, and the exact verified-data requirement is pinned; the decisive run stays [O]/unbuilt pending verified inputs. No present-tense discriminator is produced — consistent with M37, M39, M46 and Module 47. The honest gain is procedural, not evidential: the program's one remaining off-[O] candidate is now a built test waiting on data, not a slogan. Falsification = discovery.
