HTML Authoring Principle

The stated authoring standard for this package, derived from VP-SPEC v1.8 (Constitution C1–C4). It binds every future edit of the VP Recent-Sequence Cascade.

One line. HTML is the single canonical body; every source subheading is rendered in full; numbers, equations, and grades are invariant; the reproducibility and inherited verification layer stays as-is; open items keep their stated reason; pages are static, semantic, retrieval-ready HTML.

1. Canonical single material — HTML (C2)

The HTML files in this package are the single canonical body. No parallel prose source for the same content ships in the distribution package — no .tex, no .md body twin. Maintaining one body in two materials causes mutual drift and destroys the reproducibility baseline, so the prose lives in HTML and nowhere else.

What is not a parallel prose twin, and therefore stays unchanged: reproducibility scripts, frozen data, computed results, figures, and inherited verification bundles that carry their own integrity manifests. These are the verification layer, not a second copy of the body.

2. Subheading-complete, no abridgement

Each source subheading (#, ##, ###) maps one-to-one to an HTML heading (h1/h2/h3), and the full text under it is rendered faithfully. No summarising, no shortening, no fragmentation. Meaning, numbers, equations, tables, lists, blockquotes, and grades are invariant (LOCK). Corrections mark, never erase. There is exactly one h1 per page.

3. Reproducibility preserved (C1)

Every quantitative claim keeps its in-package reproduction path. The deterministic scripts (SEED = 19), the frozen primary data, and the double-SHA-256 self-gates are the verification layer and are not rewritten. The HTML shows the value; the code regenerates it; the gate proves zero drift. The package integrity manifest (MANIFEST.sha256) is regenerated by the documented recipe — per-file sha256 plus a SEED-19 double-SHA-256 ROOT-CHAIN over sha256(sha256(file_bytes).digest()).

4. Open items keep their reason (C3)

Any [O] or otherwise irreproducible quantity keeps grade [O] and states its specific obstacle in the body. The grade vocabulary — [F] forced/derived · [V] verified · [L] leaning · [O] open — is preserved verbatim from the source; precedence is F > V > L > O; nothing downstream launders an [O] upward.

5. Retrieval-readiness (C4)

Pages are static, semantic HTML with no JS-rendered body. Each document opens answer-first where the source provides a one-line summary; sections are self-contained; structured data ships in <head> (JSON-LD: ScholarlyArticle + BreadcrumbList, author ORCID, license, inherited DOIs). URL-layer signals (canonical, sitemap.xml, robots.txt) are assigned at the site-merge phase (VP-SPEC §3/§8) and are not fabricated in the handoff package.

6. No inline style or script

One shared stylesheet (assets/site.css); no inline CSS or JS; no KaTeX/MathJax span residue. Inline mathematics is Unicode text (c² = B/ρ); display equations, where present, are rendered SVG whose alt LaTeX is accessibility metadata — part of the HTML material, not a separate source.

7. Bidirectional chronology firewall preserved

Every past-occurrence statement stays [O] in both directions; absolute dates are RECORD only; the firewall is symmetric. The conversion never promotes a firewalled statement and never imports interpretation or dates as load-bearing.

8. Link integrity

Internal links to converted files are rewritten .md → .html. Links to frozen inherited bundles (which remain .md) and all external DOI/URLs are left unchanged, so the navigation reflects reality: this package's prose is HTML, the inherited verification bundles are kept in their original form.

9. Deterministic, content-faithful conversion

Markdown → HTML is performed by a real parser, never by hand transcription, so numbers and tables are byte-faithful. The same input yields the same output. The build is recorded so any reviewer can reproduce the canonical HTML and the regenerated manifest from the package alone.

Falsification = discovery — a refutation is a finding. No-tuning · LOCK → Derive → Gate.
